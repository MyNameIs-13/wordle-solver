# Blazor Server, not WebAssembly

We chose Blazor Server over Blazor WebAssembly for this single-page utility. The solver is a stateless-per-circuit, no-persistence tool with no offline or static-hosting requirement, and Blazor Server avoids shipping the .NET runtime and WordList payload to the browser on every load. The tradeoff — a server process and a live SignalR connection are required, and every UI interaction (including live/reactive recomputation, ADR-0002) round-trips to the server — was accepted because that round-trip cost is small for a ~5,700-word constraint filter and we have no static-hosting constraint pushing toward WASM.
